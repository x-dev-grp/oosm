# Endpoint inventory — authorisation & tenant gating

Generated by static parsing of every `@RestController` / `@Controller` under `modules/*/src/main/java` (read-only review, 1426 endpoints:
330 declared directly in controllers + 1096 inherited from `BaseController`/`BaseControllerImpl`, which every controller that
`extends BaseControllerImpl` exposes automatically unless overridden).

**Totals:** 1426 endpoints, 20 with `@PreAuthorize` (class or method), 1195 flagged rows.

## How to read the columns

* **Guard(s)** — `@PreAuthorize` expression (class+method), explicit in-method checks found in the handler body
  (`PermissionSupport.requireAction`, `SecurityUtils.isOosmAdmin()` …) and, where verified manually, checks enforced in the
  service layer (`svc:`). `NONE beyond authenticated` = the only control is `anyRequest().authenticated()` in
  `AuthServerConfig.apiSecurityFilterChain` / `authorizationServerSecurityFilterChain`.
* **Anonymous** — `AuthServerConfig.publicEndpointsFilterChain` (Order 1) permits without authentication:
  `/actuator/health/**`, `/api/public/**`, `/api/security/user/auth/**`, `/api/security/user/me/refresh-session`.
  Those rows are shown as `PERMIT ALL (anonymous)` / `[anonymous chain]`.
* **Module gate** — result of `TenantModulePathResolver.requiredModules(path)`: `exempt` (explicitly skipped), `none`
  (no rule matches → never gated), or the module(s) the tenant must have enabled. **Caveat (AUTHZ-03):** the filter is
  registered as a plain servlet filter with `@Order(50)` while `TenantFilter` has no order (lowest precedence), so
  `TenantContext` is still `null` when the module filter runs and the gate is very likely a no-op for every request.
  The column therefore shows the *intended* gate.
* **Inherited endpoints** (`(inherited)`) come from `BaseController`: `GET /fetch/{id}`, `GET /fetchAll`, `GET /fetchAllPageable`,
  `POST ""`, `PUT ""`, `DELETE /remove/{id}` (hard delete), `DELETE /delete/{id}` (soft delete), `POST /export/{pdf,csv,excel}`,
  `POST /advanced/search`, `GET /qr/{entityType}/{entityId}`, `GET /resolve/{publicCode}`, `GET /search/by-code`.
  None carries any annotation-based authorisation; `findById`/`update`/`remove`/`delete`/`genQr` are **not** tenant-scoped
  and `advanced/search` + exports honour a client-supplied `filterTenant` flag (see AUTHZ-01/02).
* **Flag** — `FLAG: write w/o authz` = state-changing verb with no method-level/in-method/service authorisation found;
  `FLAG: sensitive read w/o authz` = read in hr/finance/security/administration or anonymous
  (`POST .../advanced/search` and `POST .../export/*` are treated as reads).
  Suffixes on inherited `BaseController` rows: `IDOR: id not tenant-scoped` (AUTHZ-02), `tenantId mass-assignable`
  (AUTHZ-05), `cross-tenant via filterTenant=false` (AUTHZ-01), `global QR fallback` (AUTHZ-10). Rows marked `(overridden)`
  keep the inherited mapping but run subclass code; only the search/export suffix is applied to them automatically.
  Service-layer checks were only verified for the security module; other modules may perform checks inside services
  that this static pass did not see (spot checks found very few — `grep PermissionSupport|SecurityUtils.is*` hits ~15 service files).
